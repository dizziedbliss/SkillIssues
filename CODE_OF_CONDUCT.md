# Code of Conduct

SkillIssues is for people who are learning, building, debugging, teaching, experimenting, and occasionally staring at an error message like it personally betrayed them.

We want this project to be welcoming to newcomers, experienced contributors, and old-school developers who remember when documentation came on paper. Everyone should be able to participate without harassment or exclusion.

## The basics

**Please:**
- be kind and assume good intent;
- explain why, not only what is wrong;
- give feedback about the code or idea, not the person;
- ask questions before making assumptions;
- welcome different experience levels, tools, opinions, and communication styles;
- credit other people's work;
- keep discussions focused, useful, and accessible.

**Do not:**
- harass, discriminate against, or personally attack people;
- troll, bait, dogpile, or deliberately derail conversations;
- make unwanted sexual or personal comments;
- publish private information without permission;
- threaten, intimidate, or encourage harm;
- dismiss someone because they are new, use a different tool, or need more context;
- submit copied work as your own;
- retaliate against someone who raises a concern in good faith.

Technical disagreement is welcome. Making someone feel small is not. We can debate architecture without turning the issue tracker into a boss fight.

## Where this applies

This Code of Conduct applies in project spaces, including:
- GitHub issues, pull requests, discussions, reviews, and commits;
- project chats, meetings, and community events;
- direct messages connected to project participation;
- public spaces where someone is representing SkillIssues or acting as a maintainer.

## Reporting a problem

If you experience or witness unacceptable behaviour, please tell a project maintainer as soon as you can.

- For a non-sensitive issue, open a GitHub issue and say that it concerns the Code of Conduct.
- For a sensitive issue, contact a repository maintainer privately through GitHub. Please do not post private details publicly.
- If there is an immediate threat to someone's safety, contact local emergency services first.

Include what happened, where it happened, who was involved, and any relevant links or screenshots. Only share what you are comfortable sharing. Reports will be handled as confidentially as practical.

## What happens next

Maintainers will review reports in good faith and may ask for more context. Depending on the situation, they may remove content, issue a warning, limit participation temporarily, or remove someone from project spaces.

The goal is a safe, useful community — not winning an argument. Maintainers are expected to follow this Code of Conduct too. If a report involves a maintainer, another maintainer should handle it where possible.

## Not sure?

Ask. It is much easier to clarify early than to repair a community after people stop showing up.

Thanks for helping make SkillIssues a place where people can learn in public, contribute at their own pace, and leave the codebase a little better than they found it.
